# Port: L2 Scenario Runner

- **Java source:** none ported. The runner drives upstream code: `GameState` (`parse`, `applyToGame`, `initFromGame`, `toString`), `PhaseHandler.setupFirstTurn`/`mainLoopStep`, and the test kit in `forge-gui-desktop/src/test/java/forge/gamesimulationtests/util/` (`PlayerControllerForTests`, which `ScenarioController` extends)
- **Go target:** `crucible/tools/l2diff` (emit, normalise, report); Java side `crucible/oracle-java/src/main/java/crucible/oracle/` (`ScenarioRunner`, `ScenarioController`, `ScenarioLobbyPlayer`), built and run by `crucible/oracle-java/l2-run.sh`
- **Status:** ADR-0060 phase 1 (report) runs locally on all 1,045 scenarios. Mapped: `startturn`, `advance`, `step`, the combat verbs, `tapformana`, `castspell`, `playland`, `resolvestack`, `passpriority` and the `attackers`, `blocks`, `attacktarget`, `targets`, `paygeneric`, `cardorder`, `cardchoice`, `confirmeffect`, `optionaltrigger`, `confirmpaycost`, `discardchoice`, `sacrificechoice`, `modechoice`, `scry`, `surveil`, `payphyrexian`, `payx`, `colorchoice`, `numberchoice`, `replacement`, `confirmreplacement`, `paysnow`, `paymonocoloredhybrid`, `paycolorlesshybrid`, `payhybridphyrexian`, `returnchoice`, `enchanttarget`, `divide`, `abilitychoice`, `playerchoice`, `discard`, `exertattackers`, `legendarykeep`, `option`, `hybridmanacolor`, `coincall`, `action` queue kinds, `paymanacost` and a refused play's `expecterror`; the scenarios using any other line are not runnable yet. Phase 2 gates: the `crucible-oracle` job in `.github/workflows/crucible-go.yml` fails unless the `differs` and Java error lists are exactly `crucible/testdata/l2-baseline.txt`

## What it does

Each `testdata/scenarios` fixture runs on both engines and the two post-states are compared, so a wrong `expect.state` stops passing silently (ADR-0060).

```bash
cd crucible
go run ./tools/l2diff emit -out /tmp/l2                 # go/<name>.state, actions/, manifest.tsv, random.txt, go-failed.txt
oracle-java/l2-run.sh /tmp/l2/manifest.tsv /tmp/l2/java # java/<name>.state|.unmapped|.error; L2_NO_BUILD=1 reuses the build
go run ./tools/l2diff diff -dir /tmp/l2                 # report.txt, diffs/<name>.diff
go run ./tools/l2diff diff -dir /tmp/l2 -baseline testdata/l2-baseline.txt  # the CI gate
```

Each run first deletes the previous run's per-scenario files in its output directory, so a reclassified or deleted scenario leaves nothing behind. `emit` plays every scenario the way `TestScenarios` does (seed 1) and records Go's final turn and phase, the point Java must stop at, each action line with the turn and phase Go ran it in (`actions/<name>.log`, S13), and whether the run drew from the game's generator after setup (`random.txt`). One JVM runs the whole manifest: the card database takes about 10 s to load and a scenario a few milliseconds. `diff` sorts each scenario into `same`, `differs`, `random` (a difference in a scenario that drew randomness, outside the gate) or `not runnable` (an unmapped line, a setup card `GameState` cannot load, a Java exception, or no Java output).

## Setup rules

How the runner turns a fixture into a Java game. Each is a place the Go harness and Java's own tooling disagree on what a fixture means.

| Rule | What | Reason |
| --- | --- | --- |
| S1 | Seats: `human` is player 0, `ai` player 1, `p<i>` player i; two seats unless the setup names a higher `p<i>` | `GameState.getPlayerState` and `fixture.playerSlot` index seats the same way |
| S2 | A setup with no `activeplayer=` gets the player of the first `startturn` | `GameState.applyGameOnThread` indexes the active player's state and throws without one; `fixture.Load` needs none |
| S3 | Every seat is a `ScenarioLobbyPlayer` whose controller is `ScenarioController`, upstream's `PlayerControllerForTests` with these overrides. It makes the seat's queued plays and actions at its priority (S13, S15), else passes until the checkpoint (S8); a player another controls gets its own `ScenarioController` (`createMindSlaveController`), since Go names a line by the player it acts for. It declares the queued attackers and blocks (`ScenarioAnswers`, one queue shared by every seat as Go's one `ScriptedController` is), nothing when none is queued. It takes targets from the `targets` queue, a card on the stack naming its spell, and drops one that is legal alone but not next to the targets already picked (a `MaxTotalTargetCMC$` sum), as Go's `trimTargetSet` does; a target illegal on its own is kept, so the spell fizzles as in Go. It asks nothing where Go asks nothing: no candidate (a legal set only under `TargetMin$ 0`), an Aura spell with one candidate, a division over one target or one point per target. It pays mana as a human does (`PlaySpellAbility.payManaCost`, which applies the cost adjustments such as a power-up's reduction), from the pool the plays filled, never by tapping. A card name chosen during `GameState`'s setup (an "as it enters" replacement) is none, as `fixture.Load` runs no such replacement; the setup's `NamedCard:` is added after. It plays each trigger as a spell, so the trigger's targets come from the queue, in upstream's order. It assigns a lone blocker's combat damage as Go does (all of it, or with trample the lethal part and the rest to what is attacked). `playSpellAbilityNoStack` plays every ability. `getAbilityToPlay` returns the first ability | An AI controller would act on its own priority. Upstream's controller cannot stop at a checkpoint and takes its answers from its own action classes. It puts a trigger on the stack with no targets (`prepareSingleSa`) and throws on any combat damage assignment. Its `playSpellAbilityNoStack` plays only a list of named cards and throws for the rest. Its `getAbilityToPlay` calls itself through `PlayerController.getAbilityToPlay` (`PlayerControllerForTests.java:494-497`, `PlayerController.java:99`), so every `PlaySpellAbility.playSpellAbility` overflows the stack (`PlaySpellAbility.java:146`) |
| S4 | `MyRandom.setRandom(new Random(1))` after `applyToGame` | The seed `TestScenarios` gives `javarand` |
| S5 | The whole run executes on Forge's game thread, the caller waits | `GameAction.invoke` hands state changes to `ThreadUtil`'s game thread; from another thread `applyToGame` returns before the setup exists |
| S6 | The JVM starts in `forge-gui-desktop/`, with `-Djava.awt.headless=true` | Forge finds `res/` relative to the working directory, as upstream's own tests run it; `GuiDesktop` needs no display |
| S7 | The reactor's `target/classes` precede the `~/.m2` jars on the classpath (`mvn -pl forge-gui-desktop -am test-compile dependency:build-classpath`) | A SNAPSHOT jar can predate the checked-out source; the oracle would quietly be old Java |
| S8 | The runner steps `PhaseHandler.mainLoopStep` until the checkpoint: the first priority Java gives at Go's final turn and phase, after its state-based actions and with the triggers they raised on the stack, where `ScenarioController` throws. When the last verb is `step`, `resolvestack` or `passpriority`, the first such priority with the stack empty. It waits until every play is made and, at a priority, every queued action taken (S13, S15). In a step that gives no priority (`PhaseHandler.givePriorityToPlayer` false: Untap, Cleanup, a damage step with no damage), reaching the step | The checkpoint model of ADR-0060: only the end state is compared. Go's `advance` stops on entering a step, after its state-based actions; its `step` plays the step's priority round out (`engine.Game.Step`); a step without priority runs no state-based check in either engine (CR 704.3) |
| S9 | The runner writes `over=`, `<player>lost=`, `<player>won=` (only once the game is over), `monarch=` and `initiative=` from Java's model, by registered seat, and adds `Protector:P<seat>` to a battle it finds by name among its controller's battles | ADR-0060: Crucible-only keys are compared, not dropped. `Player.hasWon` is true for any player with an outcome and no loss, which only means a win at game end |
| S10 | Seats in Java's text go back to the registered seat (`Game.getRegisteredPlayers`): `p<i>` key prefixes and the `Owner`, `EnchantingPlayer`, `Protector` tokens, never a counter type such as `P1P1`. `activeplayer` is written from `PhaseHandler.getPlayerTurn`, and a verb's player is looked up by registered seat | `GameState.initFromGame` numbers by `Game.getPlayers`, which drops a player who lost, so the survivors' `p<i>` shift and a lost active player is `p-1` |
| S11 | A setup card's `Damage:` is marked after `applyToGame`, then the runner runs `checkStateEffects(true)` once more | `applyGameOnThread` marks damage and runs its load-time pass before `copyLastState`, so no Moved replacement sees the lethal damage (Rest in Peace's Bears reach the graveyard). `fixture.ApplyStateEffects` runs that pass with the replacements in effect; Java settles the same board that way at its first priority |
| S12 | A setup card outside the common card pool (a Scheme, a Plane) makes the scenario not runnable | `GameState.processCardsForZone` looks cards up in `getCommonCards` only (`GameState.java:1305`) and drops the rest with a line on stderr, so Java would play a different board |
| S13 | `tapformana`, `castspell` and `playland` are plays, each with the turn and phase Go ran it in. The seat makes the next play at its first priority in that turn and phase: it plays the card's first spell or land ability through `PlaySpellAbility.playSpellAbility`, a refusal an error. A `tapformana` is made at whichever seat's priority comes first, by the source's controller, for the named color (choosing that color for any-color mana). A play after a `resolvestack` or `passpriority` waits for an empty stack. A spell a Play effect casts goes through `PlaySpellAbility.playSpellAbility` too (`playSaFromPlayEffect`), its targets from the queue. A mana cost the pool cannot pay takes the `tapformana` plays of the current step first: an attack cost is paid in the declare-attackers turn-based action, before the step's priority (CR 508.1g) | Go's harness acts outside the priority loop; Java acts only when it is asked, at a priority. The stack between two casts is what `resolvestack` drained in Go |
| S14 | A `resolvestack` in Untap or Cleanup makes the scenario not runnable | Go's harness resolves there; Java gives no priority there (CR 502.4, 514.3), so its triggers wait for the next step |
| S15 | A `queue action <player> ...` line is due at the priority round that takes it in Go: the next `passpriority`'s turn and phase, or the step a `step` line enters. The player takes it at their first priority at or after that point, once every earlier play is made; an action of a later round than the one before, or after a `resolvestack` or `passpriority`, waits for an empty stack. `pass` passes, `cast` and `playland` play as S13, `tapformana` taps, `activate N` and `manaability N` activate the card's Nth ability: its `A:` lines, then those its keywords and granting effects add, in `CardState.getSpellAbilities` order after the basic spell or land ability, as Go's `abilityAt` counts them. A door, `unlockdoor`, `foretell`, `plot`, `suspend` and `turnfaceup` are unmapped. A checkpoint in a step without priority does not wait for queued actions | Go's `ScriptedController` keeps one action queue per player, asked at each priority (`TakeAction`); a step without priority asks no one, so what it does not take stays queued |
| S16 | A `queue cardchoice` answer is popped by whichever of `chooseCardsForEffect`, `chooseSingleEntityForEffect`, `chooseEntitiesForEffect`, `chooseSingleCardForZoneChange`, `chooseCardsForZoneChange` (a multi-card hidden search, which upstream's test controller answers with nothing), `chooseCardsToDiscardFrom`, `chooseCardsToRevealFromHand`, `chooseCardsToDiscardUnlessType`, `chooseCardsToDelve`, `chooseCardsForCost`, `choosePermanentsToSacrifice` (devour, exploit) and `ScenarioCostDecision`'s exile, forage (three graveyard cards), put-counter (blight) and reveal cost parts is asked first while it fits: every id one of the options, the count within the question's minimum (0 when optional) and maximum. A question it does not fit gets the upstream default answer. An answer left queued at the checkpoint is a Java error | Go asks one `ChooseCardsForEffect` where Java splits the question by purpose; the fit test keeps an answer for the question Go asked, and the leftover check catches a Java run that never asked it |
| S17 | An `expecterror refused castspell` or `expecterror refused playland` line is a play Java must refuse too: the card offers no playable spell or land ability, playing it fails, or its turn and phase pass with no priority for the seat. A play that goes through is a Java error. After a refusal the seat's priority is the checkpoint when it is due, before the seat passes the step away. A target set below the ability's minimum fails the selection, as `TargetSelection`'s does | Go's harness reports the refusal as an error and changes nothing; a Java play would leave a state Go never had |
| S18 | A play in turn 1's Draw step makes the scenario not runnable | Go's `advance` walks through the first player's skipped draw step (CR 103.8a, `drivenSkips` is the driver's only), Java skips it and gives no priority there |
| S19 | A `paymanacost` line is a play (S13): at the seat's priority in Go's turn and phase, the cost (X from the `payx` queue) is paid through `applyManaToCost` on behalf of an empty ability, as a spell's is. A play before any `startturn` (turn 0) makes the scenario not runnable. The 13 payment scenarios that paid outside any turn now start turn 1 and pay in its main phase; the 10 that load mana with `manapool=` keep turn 0, since the pool empties as the steps pass | Go's `Game.PayManaCost` pays outside the priority loop, and Go's harness acts with no turn at all; Java needs a priority to act at |
| S20 | A `castspell` line's `face` argument casts the card's second face (an Adventure, Omen, Aftermath, Vengeance or Disturb spell, a Split card's right half: a spell ability of any state but `Original` and `LeftSplit`), `fuse` a Split card's fused spell, the one `AbilityFactory.buildFusedAbility` puts on the `Original` state | Go's `CastFace` and `CastFused` (`face.go`) pick the face by name; Java offers every face's spell from `getAllPossibleAbilities` |
| S21 | A `targets stack:N` entry is the spell or ability the game's Nth push onto the stack put there, still on it: the runner records each push from `GameEventSpellAbilityCast` (`MagicStack.java:379`, posted on the game thread) and finds that stack instance by id | Go's `StackItemID` counts every `PushAbility` from 1 (ADR-0041); Java's stack instance ids come from a counter shared by every game in the JVM, so only the push order maps |
| S22 | A spell with more than one way to cast it takes the next `queue option` answer, an index into the ways Java offers: the card's castable spells in `getAllPossibleAbilities` order (the printed spell, then its keyword and alternative-cost spells: Emerge, a Fireblast `AlternativeCost` static, Morph). With none queued it casts the first. An `option` asked anywhere else is not answered, so one queued for it is a leftover (a Java error) | Go's `chooseCastOption` indexes its `castOptions` the same way (the hand cast first) and asks only when there is more than one |

## Not ported yet

- `ScenarioController`'s answers for the other queue kinds (ADR-0060), Go's defaults and panics, and dividing combat damage among several blockers (`queue damage`)
- The other verbs and queue kinds. By the first unmapped line per scenario: `resolvestack` in Untap or Cleanup 11, `paymanacost` at turn 0 10, `queue startingplayer` and the combat `expecterror` forms 4 each, `queue keephand` and `damage` 3 each, `queue sector`, `battleprotector`, `run` and `foretell` 2 each
- A seat's own order of its simultaneous triggers: they go on the stack in upstream's list order, Go's in its default order (`queue triggerorder`, which no scenario queues)
- A created id (ADR-0059, open plan R21a-c)
- Go's `ScriptedController` does not fail on an answer left queued; the Java leftover check found four such stale lines, now removed: two `queue confirmpaycost` (Rathi Assassin, Blood Moon), a `queue targets` for a spell with no legal target (Raise Dead in the Control Magic scenario) and one for a spell that targets nothing (Ribbons)
